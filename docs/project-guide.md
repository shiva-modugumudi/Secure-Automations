# Project Documentation Guide

Use these sections in each project's README. Replace the prompts with verified project details.

## Overview and status

Describe what the project does and whether it is planned, in development, or working with documented validation.

## Manual problem

Explain the recurring SOC task, why it consumes analyst time, and which decisions remain with the analyst.

## Inputs and outputs

Describe accepted input formats, required fields, generated output, and a sanitized example.

## Workflow

Explain the processing steps, integrations, error handling, and any analyst approval points.

## Technologies and requirements

List actual technologies, supported versions, dependencies, API permissions, and configuration requirements. Use placeholder environment variable names for secrets.

## Setup and usage

Provide tested installation and execution commands, followed by expected sample output.

## Validation

Record the environment and checks performed, including invalid input and integration failure behavior where applicable.

## Results

Describe observed benefits. If measuring time saved, record the manual baseline, automated duration, sample size, and measurement method. Label unmeasured benefits as expected, not proven.

## Limitations

Explain unsupported cases, data handling constraints, and remaining manual work. For AI workflows, document how outputs are checked and how tool actions are controlled.

## Next steps

List specific improvements without presenting them as implemented features.
